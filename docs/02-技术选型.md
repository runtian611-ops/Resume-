# 02 · 技术选型

> 目标：为「个人简历 & 作品集网站」选定一套**轻量、稳定、易部署**的技术方案，并说明为什么选择纯静态方案。

---

## 一、技术栈总览

| 层 | 选型 | 版本 | 用途 |
| --- | --- | --- | --- |
| 前端框架 | Vue 3 | ^3.5 | 组合式 API，组件化开发页面区块 |
| 构建工具 | Vite | ^6.0 | 极快的开发启动与生产构建 |
| 样式 | Tailwind CSS | ^3.4 | 原子化 CSS，响应式与明暗主题 |
| 图表（架构图） | Mermaid | ^11 | 项目详情页渲染架构图（按需动态加载） |
| 语言 | JavaScript（ESM） | — | 简洁，无 TS 编译成本 |
| 部署 | GitHub Pages | — | 静态托管，免服务器 |
| 简历 PDF | 静态 PDF 文件 | — | ATS 友好，一键下载 |

**明确不使用**：后端框架、数据库（MySQL/Redis 等运行时）、服务端渲染框架（Nuxt/Next）。原因见下文。

---

## 二、选型理由

### 2.1 Vue 3（而非 React）

- **组合式 API**：逻辑复用清晰，主题切换、滚动入场等逻辑可用 composable 封装；
- **单文件组件（SFC）**：模板 + 脚本 + 样式集中，便于按区块拆分（Hero/About/Skills/Projects…）；
- **中文生态**：Element Plus 等组件库与中文文档丰富，与求职者技术栈（Vue3 前端）一致；
- 本项目无需复杂状态管理，Vue 的响应式已足够，不引入 Pinia/Vuex。

### 2.2 Vite（而非 Webpack）

- 开发服务器毫秒级冷启动、极快的 HMR；
- 生产构建基于 Rollup，产物可做代码分割（Mermaid 按需加载）；
- 配置简单，`base: './'` 即可适配 GitHub Pages 子路径。

### 2.3 Tailwind CSS（而非手写 CSS / UI 组件库）

- **原子化**：快速搭建响应式布局（移动端优先的 `sm/md/lg` 断点）；
- **明暗主题**：通过 CSS 变量 + `darkMode: 'class'` 轻松实现双主题；
- **体积可控**：生产构建只保留用到的类，未使用样式会被剔除；
- 相比直接引入 Element Plus / Bootstrap，Tailwind 更轻量，视觉更「高级克制」，不会出现组件库的千篇一律感。

### 2.4 Mermaid（架构图，按需加载）

- 项目详情要求展示「Mermaid 架构图」；
- Mermaid 体积较大，故通过**动态 import** 做代码分割，仅在用户打开项目详情时才加载，保证首屏不加载它。

### 2.5 静态 PDF 简历

- 简历 PDF 为项目内的静态文件（`public/resume/`），`<a download>` 直接下载；
- PDF 由「同一份简历内容」生成，保证与网站描述一致，且排版 ATS 友好（文本可选中、无图片化文字、结构清晰）。

## 三、替代方案对比

### 3.1 前端框架

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| Vue 3 + Vite | 轻量、启动快、中文生态好、与求职者技术栈一致 | 生态规模略小于 React | ✅ 采用 |
| React + Next.js | 顶级作品集多、SSG 好 | 引入框架复杂度、非求职者主栈 | ❌ 不采用 |
| 纯 HTML/CSS/JS | 零依赖、加载最快 | 维护成本高、组件复用差、难做主题/交互 | ❌ 不采用（仅作「轻量下限」参考） |

### 3.2 样式方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| Tailwind CSS | 原子化、响应式强、体积小 | 需了解工具类 | ✅ 采用 |
| 手写 CSS 变量 | 完全可控 | 响应式/维护成本高 | ⚠️ 部分采用（主题变量） |
| Element Plus / Bootstrap | 组件现成 | 体积大、风格同质、不够「高级」 | ❌ 不采用 |

### 3.3 部署方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| GitHub Pages | 免费、免服务器、与代码同仓 | 仅静态 | ✅ 采用 |
| Vercel / Netlify | 体验好 | 多一个平台账号、迁移成本 | ❌ 不采用 |
| 自有服务器 + Nginx | 可控 | 需运维、有成本，违背「无服务依赖」 | ❌ 不采用 |

## 四、为什么选择纯静态方案（无后端、无数据库）

1. **场景匹配**：简历/作品集是「读多写少」甚至「只读」的展示型站点，没有用户登录、评论、动态数据等需要服务端的能力；
2. **稳定可靠**：纯静态无运行时依赖，GitHub Pages 托管，不存在服务器宕机、数据库连接失败等风险；
3. **加载快**：静态资源可走 CDN，首屏快、无接口等待；
4. **零成本、零运维**：免服务器、免数据库、免备案（使用 GitHub Pages 域名时）；
5. **内容即代码**：简历内容集中在数据文件，改简历 = 改一个文件 + 重新打包，可版本化管理、可溯源；
6. **满足 ATS 简历需求**：PDF 简历本身是静态文件，不需要动态生成。

> 结论：静态方案与「打开稳定、加载快、无服务依赖」的核心目标完全一致。
