# 01 · 需求分析

> 项目名称：Resume- 个人程序员简历 & 作品集网站
> 求职者：牛润田　｜　求职岗位：Java + AI 全栈开发工程师
> 面向对象：HR / 技术面试官

---

## 一、项目概述

本项目是一份**纯静态前端**的个人简历与作品集展示网站，用于 Java 后端求职场景。它把「简历」与「作品集」合二为一：HR 打开网页即可快速了解求职者的基本信息、技术栈、项目经历与实习经历，并一键下载 ATS 友好的 PDF 简历。

核心诉求一句话：**让 HR 在 3 秒内知道「你是谁、会什么、怎么联系」，并能快速读到真实、量化的项目成果。**

### 项目定位

| 维度 | 说明 |
| --- | --- |
| 类型 | 个人简历 + 作品集展示站（单页多区块） |
| 形态 | 纯静态前端，可一键部署 GitHub Pages |
| 受众 | HR、技术面试官、用人部门 |
| 内容 | 真实简历数据，严禁编造经历，网站与 PDF 完全一致 |
| 语言 | 中文 |

## 二、受众分析（HR 视角）

HR 阅读一份简历/作品集的时间极短，关注点是「**匹配度 + 可信度 + 可获取性**」。下表把 HR 的隐性需求映射为网站设计。

| HR 关注点 | HR 的真实疑问 | 网站对应设计 | 实现说明 |
| --- | --- | --- | --- |
| 你是谁 | 姓名、岗位、学历、现居地 | Hero 区 + 关于我 | 首屏展示姓名、求职岗位、一句话定位、学历/城市 |
| 会什么 | 技术栈是否匹配 JD | 技术栈区块 | 标签/图标分组展示（Java 后端、AI、中间件、前端等），**不用百分比进度条** |
| 做过什么 | 项目真实性、难度、成果 | 项目作品集卡片 + 详情 | 每个项目含简介、技术标签、业务背景、架构图、难点、量化成果 |
| 可不可信 | 是否有源码/演示、经历是否真实 | 项目链接 + 时间线 | 附 Gitee/GitHub 源码链接、实习/教育时间线 |
| 怎么联系 | 邮箱、电话、主页 | 联系区块 + Hero 图标 | 邮箱、电话、GitHub、Gitee 一键可达 |
| 想存档 | 能否下载一份标准简历 | 「下载简历 PDF」按钮 | ATS 友好 PDF，内容与网站一致 |

### HR 场景细节

- **移动端阅读**：HR 常在手机上快速翻阅，页面必须完整移动端自适应；
- **打印/导出**：HR 可能需要把简历转给同事，PDF 需排版规范、可被 ATS 解析；
- **克制观感**：过度动画/特效会被视为「不专业、浮夸」，动画仅做点缀。

## 三、功能需求

### 3.1 完整功能清单

| 编号 | 模块 | 功能点 | 优先级 | 说明 |
| --- | --- | --- | --- | --- |
| F1 | 顶部导航 | 锚点导航（关于/技能/经历/项目/联系）+ 主题切换按钮 | 高 | 移动端折叠为汉堡菜单 |
| F2 | Hero 区 | 姓名、求职岗位、一句话简介、学历/城市、下载简历 PDF 按钮、跳转项目入口、社交图标 | 高 | 首屏即回答「你是谁」 |
| F3 | 关于我 | 个人简介、求职意向、教育背景、在校荣誉 | 高 | 数据亮点卡片 |
| F4 | 技术栈 | 分组展示 Java 后端 / AI / 前端 / 中间件等技能标签 | 高 | 禁止百分比进度条 |
| F5 | 项目作品集 | 项目卡片网格：名称、一句话简介、技术标签、截图/占位图、源码链接、演示链接 | 高 | 点击卡片进入详情 |
| F6 | 项目详情 | 业务背景、Mermaid 架构图、技术难点、解决方案、量化成果 | 高 | 弹窗或展开式详情 |
| F7 | 实习/经历时间线 | 教育经历 + 实习经历，垂直时间线 | 高 | 突出时间与量化成果 |
| F8 | 联系模块 | 邮箱、电话、GitHub、Gitee | 高 | 图标集中呈现 |
| F9 | 明暗主题切换 | 浅色/深色双主题，记忆用户选择 | 中 | 默认跟随系统，防闪烁 |
| F10 | 下载简历 | 一键下载 ATS 友好 PDF | 高 | 内容与网站一致 |
| F11 | 页脚 | 版权、备案信息、返回顶部 | 低 | — |

### 3.2 页面结构（单页多区块）

```
Hero → 关于我 → 技术栈 → 实习/经历时间线 → 项目作品集 → 联系
```

## 四、非功能需求

| 类别 | 需求 | 目标值 |
| --- | --- | --- |
| 性能 | 首屏加载快 | 首屏关键资源最小化，LCP 尽量 < 2s |
| 性能 | 图片懒加载 | 项目截图/头像 `loading="lazy"` |
| 性能 | 依赖克制 | 仅 Vue3 + Tailwind + Mermaid（Mermaid 按需动态加载） |
| 响应式 | 完整移动端自适应 | 移动端单列 → 平板两列 → 桌面三列 |
| 可访问性 | 语义化标签、对比度 | 深/浅主题均保证文字对比度 |
| 可访问性 | 动效可关闭 | 尊重 `prefers-reduced-motion` |
| 可维护性 | 内容与代码分离 | 简历数据集中在 `src/data/resume.js` |
| 内容一致性 | 网站与 PDF 一致 | 同一份数据源撰写，严禁编造 |
| 部署 | 无后端、无数据库 | 纯静态，可直接托管 GitHub Pages |

## 五、约束条件

1. **纯静态**：不开发后端、不使用 MySQL 数据库，全部内容写在前端代码/Markdown 中；
2. **技术栈固定**：Vue3 + Vite + Tailwind CSS；
3. **真实不编造**：所有简历、项目介绍必须真实，网站描述与简历 PDF 保持完全一致；
4. **克制动效**：避免 WebGL/粒子等炫技，保证可读性优先；
5. **中文交付**：代码、文档、注释全部使用中文；
6. **可溯源**：所有调研参考仓库链接写入 `04-UI调研总结.md`。
