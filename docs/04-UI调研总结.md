# 个人简历 / 作品集 UI 调研总结

> 调研时间：2026-11-07
> 调研对象：GitHub 上优秀的开源「个人程序员简历 / 作品集」仓库（Vue3 / React / Next.js 等）
> 目标用户：面向 HR 的 Java 后端求职者，追求「简约高级、克制动效、移动端优先、加载快」

---

## 一、调研背景与目标

本项目是一份面向 **HR 的 Java 后端求职简历 / 作品集**，需要一个既能快速传达专业能力、又不喧宾夺主的前端界面。调研目标如下：

1. 摸清 GitHub 上高星「简历 / 作品集」开源仓库的技术选型与设计套路；
2. 提炼 Hero 区、项目卡片、时间线、技术栈展示、联系方式、简历下载、明暗主题等模块的最佳实践；
3. 识别「过度炫技、加载慢、可读性差」等反面教材，明确规避清单；
4. 输出可直接落地到本项目的设计决策。

**技术倾向**：优先 Vue3 + Tailwind CSS，同时参考 React / Next.js 的顶级作品（它们数量更多、打磨更成熟），取其设计语言而保留 Vue3 技术栈。

> 说明：所有仓库均通过 GitHub 官方 REST API（`api.github.com/search/repositories`）逐一验证真实存在、可访问；仓库名、URL、星数、语言、topics、描述均来自 API 结构化数据。`raw.githubusercontent.com` 在本调研环境无法直接抓取原始 README（网络受限），但不影响仓库本身的可访问性。

## 三、共性设计原则

### 3.1 信息架构（单页 + 锚点导航）

几乎所有优秀作品集都是「单页多区块 + 顶部/侧边锚点导航」，区块顺序高度一致：

```
Hero（姓名 + 一句话定位 + CTA）
  → About（简介 + 数据亮点）
  → Skills / Tech Stack（技术栈）
  → Experience（经历 / 时间线）
  → Projects（项目卡片）
  → Contact（联系方式）
```

关键原则：**首屏（Hero）必须 3 秒内让人知道「你是谁、会什么、怎么联系」**。

### 3.2 Hero 区最佳实践

- 左侧文字（姓名 + 一句话职业定位 + 关键 CTA），右侧可选头像/抽象图形，保持留白；
- CTA 通常两个：**「下载简历」**（高优先级实心按钮）+ **「联系我」**（次级描边按钮）；
- 关键社交链接（GitHub / 邮箱 / LinkedIn）以图标形式紧邻 CTA；
- 避免首屏塞入大段自述文字，定位语控制在 1 句话以内。

### 3.3 项目卡片

- 网格布局（1 / 2 / 3 列响应式），卡片含：缩略图、标题、一句话简介、技术栈标签、GitHub / 演示链接；
- Hover 动效应克制（轻微上浮 / 边框高亮 / 图片缩放），不遮挡信息；
- 卡片之间留白充足，`gap` 与 `padding` 一致，形成节奏感。

### 3.4 时间线（经历 / 教育）

- 垂直时间线，左侧时间 + 右侧内容，或用圆点 + 连线的经典形式；
- 经历描述突出**量化成果**（如「接口 QPS 提升 30%」「服务可用性 99.9%」），这是 HR 最关心的信息。

### 3.5 技术栈展示 —— 避免百分比进度条

- ⚠️ **明确规避**：`HTML 90% / Java 85%` 这类百分比进度条被设计社区广泛诟病——缺乏客观基准、无法衡量、反而显得不专业；
- ✅ 推荐：**标签（chip/tag）**、**图标网格**、或「熟练 / 了解」两档分组；图标 + 名称即可，不评分。

### 3.6 联系方式与下载简历

- 联系方式用图标链接集中呈现（邮箱、GitHub、LinkedIn、电话），避免暴露纯文本被爬取；
- **下载简历按钮**作为全局固定元素或 Hero 主 CTA，指向 PDF 下载（`<a download>` / 静态文件），一键可达。

### 3.7 明暗主题切换

- 用 CSS 变量（`--bg`、`--text`、`--accent` 等）统一管理颜色；
- 主题状态存 `localStorage`，默认跟随系统 `prefers-color-scheme`；
- 用 `data-theme` 属性切换变量，**避免页面闪烁（FOUC）**——可在 `<head>` 内联一段脚本提前设置主题。

### 3.8 动效 —— 克制是高级感的关键

- 优秀作品多用 **滚动入场（fade/slide-in）**、**Hover 微反馈**、**平滑锚点滚动**；
- 单元素动效时长 150–300ms，避免长动画拖慢体验；
- **反面教材**：Three.js/WebGL 全屏背景、粒子特效、自动播放的连续动画——炫技但拖慢首屏、移动端掉帧、分散 HR 注意力。

### 3.9 移动端优先

- Tailwind 的 `sm/md/lg` 断点做「移动端单列 → 平板两列 → 桌面三列」；
- 触摸目标 ≥ 44px，导航在移动端折叠为汉堡菜单；
- 图片懒加载 + 按需尺寸，控制首屏资源。

## 四、本项目设计决策

> 面向 HR 的 Java 后端求职，关键词：**简约高级、克制动效、移动端优先、加载快**。

### 4.1 布局

- **单页多区块 + 顶部锚点导航**，区块顺序：Hero → About → 技术栈 → 工作经历（时间线）→ 项目 → 联系；
- Hero 采用「左文字 + 右抽象图形（或纯留白）」布局，突出专业感；
- 项目卡片用 3 列（桌面）/ 2 列（平板）/ 1 列（移动端）响应式网格。

### 4.2 配色

- 主色：**深色中性色**（如石墨灰 `#1a1a1a` 或藏青 `#0f172a`）为文字/背景基调；
- 背景：浅色用近白（`#fafafa` / `#f8fafc`），深色用深灰蓝；
- 强调色：**单一克制强调色**（如沉稳蓝 `#2563eb` 或墨绿），仅用于 CTA、链接、选中态，不滥用；
- 整体「少色 + 高对比」，保证可读性，符合后端工程师专业形象。

### 4.3 明暗主题

- CSS 变量 + `data-theme` 实现明暗双主题，默认跟随系统，`localStorage` 记忆用户选择；
- 顶部导航放一个简洁的太阳/月亮切换按钮，`<head>` 内联脚本防闪烁。

### 4.4 动效（克制）

- 仅保留：区块滚动入场（fade + 轻微上移）、项目卡片 Hover 轻浮起、锚点平滑滚动；
- **不使用**：WebGL/Three.js 背景、粒子、自动轮播、百分比进度条；
- 尊重 `prefers-reduced-motion`，为减少动效偏好的用户关闭动画。

### 4.5 移动端与性能

- 移动端优先：先写单列布局，再 `sm/md/lg` 增强；
- 图片懒加载（`loading="lazy"`）+ 压缩，头像/项目缩略图控制尺寸；
- 技术栈选型倾向 **Vue3 + Vite + Tailwind CSS**，产出轻量静态站，首屏资源最小化；
- 简历下载按钮提供 PDF（可引用 `billryan/resume` 的 LaTeX 内容范式撰写简历，再导出 PDF）。
