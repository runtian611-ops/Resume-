# 05-部署方案

> 本项目为纯静态站点，无后端、无数据库，最终构建产物是一份纯静态文件（HTML/CSS/JS），可部署到任意静态托管平台。本文以 **GitHub Pages** 为主进行说明。

## 1. 本地开发启动方式

### 环境要求

| 依赖 | 版本要求 | 说明 |
| --- | --- | --- |
| Node.js | ≥ 18（推荐 20/22） | 运行 Vite 与打包 |
| npm | 随 Node 附带 | 包管理工具 |

### 启动步骤

```bash
# 1. 进入项目目录
cd Resume-

# 2. 安装依赖（首次或依赖变更后执行）
npm install

# 3. 启动开发服务器（热更新）
npm run dev
```

启动成功后终端会提示访问地址，默认 <http://localhost:5173>。

## 2. 打包命令

```bash
npm run build
```

- 产物输出到 `dist/` 目录
- `vite.config.js` 中已配置 `base: './'`（相对路径），保证部署到 GitHub Pages 子路径（如 `/Resume-/`）时资源也能正确加载

## 3. 本地预览打包产物

```bash
npm run preview
```

该命令会以生产模式本地启动一个静态服务器，预览 `dist/` 的实际效果，访问地址终端会提示（默认 <http://localhost:4173>）。

## 4. GitHub Pages 部署教程

### 4.1 前置条件

- 仓库地址：<https://github.com/runtian611-ops/Resume->
- 分支：`main`

### 4.2 方式一：GitHub Actions 自动部署（推荐）

仓库已内置 `.github/workflows/deploy.yml`，流程为：推送 `main` → 自动 `npm ci` → `npm run build` → 部署产物到 GitHub Pages。

1. 将代码推送到 `main` 分支
2. 打开仓库 **Settings → Pages**
3. 在 **Build and deployment → Source** 选择 `GitHub Actions`
4. 首次推送后，Actions 会自动执行并部署；之后每次推送 `main` 都会自动更新

> 注意：GitHub Actions 要求仓库中存在 `package-lock.json`，首次 `npm install` 后会自动生成，请一并提交。

### 4.3 方式二：手动部署到 gh-pages 分支

```bash
npm install
npm run build

# 把 dist/ 提交到 gh-pages 分支
git subtree push --prefix dist origin gh-pages
```

然后在 **Settings → Pages** 中将 Source 设为 `gh-pages` 分支的 `/ (root)`。

### 4.4 开启 Pages 后的访问链接

部署成功后，公网访问链接为：

> <https://runtian611-ops.github.io/Resume-/>

## 5. 部署后自检清单

- [ ] 首页正常加载，标题、Hero、技术栈、项目、经历、联系模块齐全
- [ ] 明暗主题切换正常，刷新后主题记忆生效
- [ ] 「下载简历 PDF」按钮可下载，PDF 可正常打开、内容与网站一致
- [ ] 项目卡片点击可打开详情弹窗，架构图正常渲染
- [ ] 手机宽度下布局正常（响应式）
- [ ] 所有外链（GitHub / Gitee / 邮箱 / 电话）可正常跳转

## 6. 常见问题

| 问题 | 原因 | 解决方案 |
| --- | --- | --- |
| 部署后页面空白 / 资源 404 | `base` 未设为相对路径 | 确认 `vite.config.js` 中 `base: './'` |
| 架构图不显示 | mermaid 按需加载失败 | 检查网络，或查看浏览器控制台报错 |
| PDF 文件名乱码 | 中文文件名在 URL 中需编码 | 已使用 ASCII 文件名 `Resume-NiuRuntian.pdf`，`download` 属性用中文名 |
| Actions 部署失败 | 缺 `package-lock.json` | 本地 `npm install` 后提交该文件 |
