## 九、`dist/` 里到底有什么（构建后）

`npm run build` 之后 `dist/` 的结构：

```
dist/
├── index.html                    # Vite 处理后的入口（引用 ./assets/...）
├── assets/
│   ├── index-xxxxxxxx.js         # 应用主 JS（打包后的 Vue 代码）
│   ├── index-xxxxxxxx.css        # 打包后的 Tailwind 样式
│   └── mermaid-xxxxxxxx.js       # Mermaid 独立 chunk（懒加载，不入首屏）
├── favicon.svg                   # 从 public/ 原样拷贝
└── resume/Resume-NiuRuntian.pdf  # 从 public/ 原样拷贝
```

- **哪些「被处理」**：`index.html`、`src/` 下的 `.vue/.js/.css` 会被编译/合并/压缩，文件名带哈希（缓存失效友好）。
- **哪些「被原样拷贝」**：`public/` 下的所有文件（favicon、PDF）。
- **哪些「不出现」**：`docs/`、`scripts/`、`package.json`、配置文件、`node_modules/`——它们只用于开发或构建，不进入线上产物。

## 十、新增文件时「放哪」的准则

| 你要加的东西 | 放哪 | 说明 |
| --- | --- | --- |
| 新的页面区块 | `src/components/XxxSection.vue` | 大区块可再拆子组件，统一在 `App.vue` 组装 |
| 新的简历数据（如奖项/新项目） | `src/data/resume.js` | **不要**散落硬编码到组件里 |
| 新的全局样式/颜色变量 | `src/style.css` + `tailwind.config.js` | 颜色统一走 `--c-*` 变量，两种主题都要补 |
| 新图片 / 可下载文件 | `public/` | 会原样进 `dist/`，路径以 `/` 开头（构建后正确） |
| 新文档 | `docs/` | 按序号递增（09、10…） |
| 新脚本 | `scripts/` | 离线工具，不进网站产物 |
| 新 CI 工作流 | `.github/workflows/` | 注意 PAT 需 `workflow` 权限 |

> 判断口诀：**「运行时要用的静态资源 → `public/`；要被编译的源码 → `src/`；给人看的说明 → `docs/`；离线工具 → `scripts/`。」**
